## 1. Sample assessment — the crux

| metric | value |
|---|---|
| raw `source='screener'` rows | 2748 (2026-05-31 → 06-29) |
| episodes (gap-and-islands, `max_gap=4` trading days) | 959 across **15** distinct entry days |
| **matured episodes** (canonical first-seen row has `fwd_return_20d`) | **146** |
| matured with `r_multiple_20d` | 144 |
| matured with a triple-barrier label (`win`/`loss`) | **49** (26 win / 23 loss) |
| matured with `fwd_return_60d` | 0 (60-bar horizon not reached) |
| **distinct entry days among the 146 matured episodes** | **1 — all `2026-05-31`** |

**Why one cohort.** The live archive began 2026-05-31. `fwd_return_20d` only fills
once 20 forward bars exist (~06-27 for a 05-31 entry). The next entry cohorts are
queued but not yet matured — 06-01 (63 episodes), 06-03 (163), 06-05 (114), … 06-27
(20). So today's matured set is exactly the first day's setups, all sharing the
**same** 20-bar forward window.

**Implication.** 146 (or the 49 labelled) is **not** 146 independent observations of
"does sub-score X predict edge." It is **one** cross-sectional snapshot of **one**
regime (the late-May→June tape). The naïve adequacy gate in `analyze.py` (which counts
rows, not cohorts) reports *"Sample looks adequate"* and even the episode-deduped
`signal_edge` marks its verdicts `trustworthy=True` (n=49 ≥ 25, minority 23 ≥ 8) — but
**neither tool checks temporal/regime independence**, which is the binding constraint
here. Per the task's guard ("if it's still thin … do NOT re-weight on noise"), this is
a stop: nominal n clears 30, but the *effective* independent sample is ≈1 cohort.

> The market context makes this concrete: the cohort's mean raw `fwd_return_20d` is
> **+8.0%** (86% up); SPY-subtracted **abnormal** return is **+9.8%** (88% beat SPY).
> A +8% / 86%-up snapshot is a single bull-tape realization — exactly the kind of
> outcome distribution that yields spurious cross-sectional correlations.

## 2. Prior-signal confirm / refute (raw rows vs episode-deduped)

The prior signals were measured on **raw** archive rows. The screener re-flags a
persisting base every day, so a base that sits 15 days and then loses contributes its
sub-scores **15×** against one shared outcome. Collapsing to one row per logical setup
(`core/archive/episodes.py`) removes that autocorrelation. The two views disagree, and
the disagreement is the finding:

| sub-score | prior | raw rows (n=769 durable) | **episode-deduped (n=49 durable)** | survives dedup? |
|---|---|---|---|---|
| `score_rs_bonus` | −0.23 **harmful** | −0.20 **harmful** | **−0.044 INERT** | **NO — refuted** |
| `score_base_age` | +0.37 beneficial | +0.30 beneficial | **+0.232 beneficial** | yes (already positive) |
| `score_high_proximity` | — | +0.11 inert | −0.267 harmful* | new, single-cohort |
| `score_box_tightness` | — | −0.06 inert | −0.182 harmful* / **+0.265 vs R** | sign-flips by target |

\* The "harmful" label **moves between sub-scores depending on raw-vs-dedup**
(rs_bonus in raw; high_proximity + box_tightness in deduped) and, for box_tightness,
**flips sign across outcome targets**. That instability — across aggregation method,
across targets, and vs the prior read (rs_bonus −0.23 → −0.044) — is itself decisive
evidence that none of these are robust. They are noise on one regime.

**Conclusion: nothing survives episode-dedup as an actionable harmful signal with a
real (multi-cohort) sample.** `score_rs_bonus`'s apparent harm is a measurement
artifact, not an engine defect.

**Decision: FLIPPED `TIGHTNESS_ADR_AWARE = True`.** The operator reviewed the A/B pack

- **Demotions** (ADR-aware pushes down) are genuine flat low-ADR drift: **GBTG** (0.51% ADR —
  a *buyout deadpin*, gapped to ~$9.34 on 05-04 and flatlining at the cash price, yet earning
  the book's top tightness 20.4 → cut to 9.0), **HIO** (0.86%, 18.6→6.5), **IX** (1.48%), **AES**
  (0.39%). These were over-rewarded by absolute-% tightness.

## 5. LPS markup gate (`LPS_RESCUE_MAX_ADVANCE_BOX = 0.21`) — **VALIDATED, KEEP 0.21**

Validation method (network-free, cache-based): re-evaluate each matured ticker as-of its
2026-05-31 entry on the **same** 5y cache under gate **ON (0.21)** vs **OFF (None)**.
Comparing ON vs OFF on identical data isolates the gate's marginal firing effect.

```
matured tickers as-of 2026-05-31: 146 (145 evaluable; SSSS has no cache history)
fire under gate OFF(None): 80     fire under gate ON(0.21): 80
DROPPED BY GATE (fires OFF, not ON): 0
  → matured barrier/durable winners dropped: 0
  → matured fwd20-up tickers dropped:        0
```

The 0.21 gate drops **zero** matured tickers and therefore **zero** winners on the only
matured cohort. Combined with the prior seed-recall validation (0/52 winners dropped at
the **tighter** 0.15), the gate is confirmed recall-safe. **Keep 0.21.**

> Note: the archive's `lps_swing_type` column is null for the 05-31 cohort (it began
> being written ~06-26, and the gate was committed 06-27 — both after this scan), so the
> gate could not be validated by reading archived swing-types; the cache re-eval above is
> the correct substitute and gives a direct ON-vs-OFF answer.
