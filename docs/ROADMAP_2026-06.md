# Chrollo — Consolidated Roadmap Brief

## 1. Current-state verdict

Chrollo is a genuinely well-built solo research instrument that punches far above "personal project" weight: the structure engine is lookahead-safe by construction (the hard part, and it's done), the narrative `read_structure` spine is the right altitude, triple-barrier labeling and bias detection in `analyze.py` are textbook-correct, the IBKR thread-service is production-grade, and the design *philosophy* (DESIGN.md) is exceptional. But the codebase is in a "brilliant engine, fragile periphery" state. Three structural debts gate everything ahead: (1) live and replay evaluation are **hand-mirrored twins** (`_evaluate_ticker` vs `_evaluate_at_date`), so no backtest is provably the live engine; (2) the entire non-price data layer (sector, fundamentals, earnings) is ad-hoc hang-prone `yfinance .info` scrapes with no provider seam; (3) the frontend is a no-router `activeTab` switchboard with five copy-pasted chart implementations and ~300 hardcoded hex values ignoring a strong token system. None of these are bugs — they're overfit-fragility and duplication that will compound hard the moment feature-building starts. The engine is *close* to freeze-ready but not there: ATR is window-dependent and there's no hashable frozen-config manifest. **Verdict: do the foldout/foundation work first; the features are downstream consumers that need almost nothing new from the engine.**

## 2. Cross-cutting themes (fix once, pay everywhere)

1. **Hand-mirrored twins everywhere.** Live/seed evaluation (`evaluation.py` vs `seed.py`), three scorer entry points (`_score_eval_context`, `backtest_watchlist._evaluate_with_reason`, seed), two `TagOut` definitions, two retry-download helpers. The pattern: shared *helpers* were folded but *orchestration* was copy-pasted. Every twin is a drift surface, and a backtest is only as trustworthy as the seed==live guarantee — which today is discipline, not code.

2. **No provider seam for non-price data.** `providers.py` is OHLCV-only. Sector/earnings/fundamentals each landed as ad-hoc `yfinance .info`/`.calendar` scrapes (in `archive_models.py`, `earnings.py`, even inside FastAPI request handlers in `prices.py`). Sectors, commodities, fundamentals, and the local agent's unattended runs are ALL blocked on this same missing seam. Fix it once → four roadmap items unblock.

3. **Schema/constant duplication with no single source of truth.** The ~150-field setup schema is hand-maintained across `SetupOut` + `SetupArchive` + `_MIGRATIONS` + `add_setup_manually` (4 edit-sites, no compiler check). Scoring constants live in `settings.py` but tag thresholds are re-hardcoded in `setupTagsData.js` (`traversalDensity 0.33` duplicates `TRAVERSAL_QUALITY_DENSITY_FULL`). In-function weights (0.40/0.35/0.25 etc.) are invisible to the knob audit.

4. **Tokens/primitives exist on paper, not at runtime.** DESIGN.md + `index.css :root` define tokens; ~300 hardcoded hex across 47 files ignore them. No `<CandleChart>`, no `Panel/StatTile/DataTable/Modal` primitives, no router. Every new surface re-hand-rolls chrome — the exact thing that makes "5 new surfaces" turn into a mess.

5. **Selection/survivorship bias is structural, and the loop has never closed.** Archive records firing setups only (no denominator), seed set is both training and test data, and yfinance can't give a point-in-time universe. The outcome math is right; there's no null/base-rate comparison and no IS/OOS split. Every win-rate number is currently uninterpretable.

6. **Window-dependent ATR + no frozen-config manifest.** ATR is an EWMA-from-origin, so gate outcomes move with cache depth (2y vs 3y). There is no single hashable artifact pinning the full algorithm state. Both are freeze blockers.

## 4. The hard sequencing question

**Foundations and the freeze must precede the feature/UI build — and the freeze must precede heavy backtesting.** The argument:

- **You cannot honestly backtest twins.** "Replay at T == live at T" is the single most important guarantee for a backtesting engine, and today it rests on a recall test, not one code path. Fold #1 (unify eval) is a *hard prerequisite* for the owner's stated #2 goal (freeze + backtest). Freezing twins freezes a lie.
- **Freeze before backtest, not after.** The frozen-config manifest + window-invariant ATR (or declaring the window part of the frozen contract) must exist *before* the walk-forward run, or the backtest measures a moving target. Stamp an **engine-config-version on every archived row** — this is what later enables IS/OOS reads and converts the eyeball-tuning loop into disciplined walk-forward.
- **The data seam gates half the features.** Sectors, commodities, fundamentals, and the unattended local agent ALL block on Fold #2. Building any of them first means N more ad-hoc `.info` scrapes that the seam refactor would then have to unwind. Do the seam once, early.
- **The frontend shell gates all UI surfaces.** Router + `<CandleChart>` + primitives are additive refactors on a clean base (the hooks-per-feature pattern survives). But adding Home/Sectors/Commodities as more `&&` branches with a 6th-7th copied chart is technical-debt-by-construction. Shell first, then surfaces are compositions.
- **Backtesting can run in parallel with UI foundation work** once the engine is frozen and eval is unified — they touch disjoint code. Fundamentals scoring depends on the data seam but not the freeze. The local agent is genuinely last (it consumes everything else's read models + traces).

**Dependency chain:** Unify-eval → Freeze+manifest → Backtest engine. Provider-seam → (Fundamentals scoring, Sectors, Commodities, Agent-unattended). Router+CandleChart+primitives → (Home, Watchlist, Alerts, Portfolio-manager UI). Schema-fold is a velocity multiplier feeding everything that adds archive fields.

## 5. Phased roadmap

### Phase 0 — Deep-clean & de-twin (the unlock) — **size: M-L**
**Goal:** raise to senior quality and remove the drift surfaces that block everything.
**Deliverables:** unify live/seed eval onto one path (Fold #1); promote `providers.py` to multi-capability seam + durable reference store (Fold #2); single-source the setup schema (Fold #3); centralize ATR-eval bar (#7); split test god-file + `pytest.ini` + un-ignore shadow fixture + prune dead tools (#9); fold the two download helpers and `TagOut` dupes. **Draws on:** structure-audit refactor_folds #1/#2, data-layer debt P1s, backend debt P1 (schema), hygiene debt P2s. **Owner want:** (1) deep-clean.

### Phase 1 — Freeze & heavy backtest — **size: M-L**
**Goal:** a reproducible frozen engine with measured *standalone* edge.
**Deliverables:** lift hidden weights to settings + **hashable frozen-config manifest** + engine-config-version stamped on archived rows (#8); make ATR window-invariant or declare window in frozen contract; add geometry **invariant/property tests** (phase ordering, S<R, no NaN, strict pivot alternation); new `tools/backtest_engine.py` reusing `compute_barrier_events`/`episodes`/`missed_winners` verbatim; **add the null/base-rate model** (random same-count draws from the day's eligible universe) — the headline edge metric becomes screener-median-MFE *minus* null-median with bootstrap CI; **MFE as primary edge metric** (not realized R — you manage exits by hand); abnormal-return vs SPY; IS/OOS via the config-version stamp; multiple-testing haircut in `analyze.py §6`. **Draws on:** backtest-research (event-study, base-rate, MFE, survivorship, walk-forward, DSR), archive-audit roadmap. **Owner want:** (2) freeze + backtest. **Honesty note:** lean on the *live forward* archive as the only survivorship-free truth; do NOT present historical yfinance re-scans as unbiased.

### Phase 2 — Scoring rework + minimal fundamentals — **size: M**
**Goal:** a defensible composite plus low-input/high-impact fundamentals, all graded-not-veto.
**Deliverables:** refactor scorer into Geometry/RS/Fundamentals axes (Fold #6); thin fundamentals layer computing exactly **5 metrics** (qtr EPS growth YoY, qtr sales growth YoY, EPS-growth acceleration, earnings surprise %, in-house RS rating) via `get_income_stmt`/`get_earnings_dates`/`.info` — **avoid the broken legacy property methods**; **percentile-rank** each metric across the scan universe (IBD-style, auto-normalizes small-caps); surface as tag chips (`⚡ RS Leader`, `Earnings Accel`) + a `days_to_earnings` warning chip; null-safe (missing fundamental → 0 weight, never drops a geometric VCP); single-source tag thresholds from the calibration endpoint. **Draws on:** scoring-audit roadmap, fundamentals-research (5-metric consensus, yfinance reachability, EDGAR as v2 backbone). **Owner want:** (3) scoring + fundamentals. **Guardrail:** geometry stays the only veto.

### Phase 3 — Market regime + sector/leadership — **size: M**
**Goal:** SPY/QQQ aggression posture + sector RS as ranking context.
**Deliverables:** upgrade the regime synthesis to a transparent **0-100 Market Health Score** (6 weighted components: index trend-template, %>50d, %>200d, distribution-pressure, net-new-highs, A-D/McClellan-style oscillator); add the missing IBD mechanics — **5%-rally distribution-day erase** + a **follow-through-day "green light" detector**; full Minervini 50>150>200 stacked-and-rising index template; compute A-D line + net-new-highs from the **own scanned universe** (free, truer signal); **divergence flag** (SPY up + breadth down = narrowing leadership); the **RS line** (`stock/SPY`) with `rs_line_new_high` as a first-class chip — the highest-ROI leadership item; sector ranking via the 11 SPDR ETFs (rs_ratio over 21/63/126d). **Draws on:** regime-research (composite, FTD, distribution erase), sector-research (RS line, IBD RS rating, SPDR proxy). **Owner want:** (4) sector + leadership + regime. **Damping:** add a "stretched" cap above ~0.85 breadth so the dial doesn't peak at tops.

### Phase 4 — UI/UX hybrid: shell, Home, Watchlist, Sectors, Commodities — **size: L**
**Goal:** the Finviz×TradingView cockpit, built on real foundations.
**Deliverables:** router + AppShell (Fold #5); `<CandleChart>` primitive + UI kit (`Panel/StatTile/GaugeTile/DataTable/Modal/Toast/Pager`) + JS theme module (`tierColor`, format helpers) + codemod hex→tokens + chart-ink token set; **Home** = Finviz "morning brief" (index/breadth strip + engine-native signal lists: New boxes today, Springs detected, HTF Re-accum, Watchlist movers, Approaching-pivot + setup-density-by-sector strip, all linking pre-filtered into screener); **Watchlist** graduates to a first-class destination with **7-color flags that also filter the screener** + per-symbol notes; **Sectors screener** (ranked table + RRG quadrant via recharts) + **Commodities/Themes screener** as a separate `core/peers/` module (theme→producer-basket map, tiered holdings adapters: etf-scraper → per-issuer CSV → SEC N-PORT, correlation-to-leader ranking) gated behind `PEER_SCREENER_ENABLED`; default screener to a **charts-grid** view with box overlays; hover-peek mini-charts. **Draws on:** frontend-audit (router, CandleChart, primitives), UX-research (morning brief, flags-filter-screener, charts-grid), lwc-v5-research (Series Primitive box, panes, createPriceLine), commodity-research (futures-pool trap, theme indirection, tiered adapters). **Owner wants:** (5) sectors + commodities screeners, (6) UI/UX hybrid + home + watchlists. **Critical trap:** ~8 of the owner's 11 example tickers (GLD/SLV/USO/UNG/WEAT…) are futures pools with **no equity constituents** — the screener must map theme→*producer-equity baskets*, not read ETF holdings naively.

### Phase 5 — Alerts, Portfolio manager, resident agent — **size: L**
**Goal:** the triggers/TP alert loop, a TradingView-like portfolio manager, and the read-only "second brain."
**Deliverables:** **Alerts engine** — rules table + scheduler evaluation pass + delivery abstraction (in-app popup + one free webhook → Telegram/Discord); tie alerts ONLY to high-conviction engine events (breakout, spring reclaim, LPS entry, HTF re-accum) so each inherits a "why fired" payload from the structure trace; cap at ~3-5/week, tiered; create-alert-from-a-price-level/box-rail; central Alerts Manager. **Portfolio manager** built on `<CandleChart>` + entry/stop/target via `createPriceLine` + fill markers, reusing the Layer-A trade-enrichment (live price/unrealized P&L/R/distance-to-stop). **Local agent** via Claude Agent SDK embedded in the FastAPI process: in-process read-only `@tool` set wrapping existing services (`/why`, `/sector`, `/plan`, `/journal`), grounded in the engine's deterministic trace (never inventing Wyckoff). **Draws on:** UX-research (alert restraint, flag/notes model), agent-research (financial-services read-only blueprint, SDK permissions). **Owner wants:** (6) alerts/portfolio-manager, (7) local agent. **NON-NEGOTIABLE GUARDRAIL:** the order-placement path is simply **not in the agent's tool surface** — `permission_mode='dontAsk'`, explicit read-only allow-list, PreToolUse deny-hook on any IBKR execution endpoint, never `bypassPermissions` (subagents inherit it). ## 7. Risks & non-obvious calls

- **yfinance fundamentals are a minefield.** The legacy property methods (`.earnings`, `.quarterly_financials`, `.quarterly_earnings`) return **empty DataFrames** in 2026 and look fine on large caps in dev then blank across small-caps in prod. Use only `get_income_stmt`/`get_earnings_dates`/`.info`. History is shallow (~4-8 quarters) — acceleration needs ~5-6 clean quarters; handle gaps gracefully. **Plan EDGAR (CompanyConcept + Frames) as the v2 backbone** but budget for XBRL concept normalization + YTD→single-quarter differencing. FMP/Alpha Vantage free tiers (250/25 calls/day) can't scan a universe and FMP's license forbids displaying data in a web app — detail-view enrichment only.
- **Backtest bias traps.** Survivorship bias via yfinance is **unfixable for historical re-scans** — never present them as unbiased; the live forward archive is the only survivorship-free truth. Without the null/base-rate model every win-rate is uninterpretable. Each eyeball-tune-rerun is an in-sample trial — apply a multiple-testing haircut before calling any sub-score "harmful." Use MFE (screener edge) not realized R (conflates screener + your discretionary exit). Daily-bar barriers have intrabar path ambiguity — document the same-bar=loss assumption.
- **ATR window-dependence is a silent freeze hazard.** The same chart from a 2y vs 3y cache gives different gate outcomes. Either make ATR windowed/window-invariant or *declare* `DAILY_STRUCTURE_PERIOD` + `STRUCTURE_EDGE_SKIP_BARS` as part of the frozen contract — pick one explicitly before backtesting.
- **Scope creep on Finviz cloning.** Do NOT rebuild the 67-criteria fundamental forest, insider/institutional panels, crypto/forex, or a full-market heatmap. Filters sit over *engine output* (tag/phase/tightness/traversal), the sector strip is derived from *screener density* not a separate pull, and density belongs only on triage surfaces (TradingView restraint the moment one ticker is in focus). Alert firehose is the other creep risk — tie to engine events and cap, or it gets muted.
- **Commodities futures-pool trap** (called out in Phase 4): naive ETF-holdings expansion returns bullion/futures contracts, not stocks. Theme→producer-basket indirection is mandatory. VanEck/Defiance/Sprott pages are JS-walled — N-PORT is the universal fallback. yfinance `funds_data.top_holdings` caps at 10 names; don't use it as the holdings source.
- **The no-auto-trade guardrail is structural, not prompt-text.** Mirror Anthropic's financial-services reference (ships *no* execution tool). The order path is absent from `allowed_tools`; `dontAsk` mode; PreToolUse deny-hook + audit log; read-only IBKR session if available; never `bypassPermissions`. Plans are DRAFTs promoted by a human click. Also: the backend cwd/config collision means any new in-process MCP module must read settings **lazily** or it crashes service boot.
- **Non-obvious call: keep the custom backtest harness — do NOT adopt vectorbt/backtrader/zipline.** Chrollo already has a correct, engine-coupled event-study harness; a framework would force re-hosting the Wyckoff engine in a foreign loop for zero gain. Steal only zipline's Pipeline *mental model* for the universe-wide base-rate computation.
- **Non-obvious call: collapse the four swing skeletons to one.** `_find_pivots`+zigzag, `pip.py`, `_collapse_swings`, and `classify_window_descent` are four definitions of "a swing." Before freezing, pick the canonical one (the L0 labeller) so the frozen engine has *one* swing definition — otherwise you freeze four near-copies and carry that ambiguity forever.
